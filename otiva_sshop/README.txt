Отправка уведомлений менеджеру о сообщении клиента

Если менеджеру не приходят уведомления с Авито, то данная фича решает эту проблему и отправляет уведомление о сообщении от клиента менеджеру на почту, попутно обновляя бизнес-метрики, что делает работу менеджеров более подотчетной.

## Overview
Возможности и основная функциональность
  - Закрепление клиента за менеджером, закрепление данных для бизнес-метрик
  - Контроль response laga менеджера  (определение загруженности менеджера)
  - Отправка сообщений менеджеру на email
Сценарии использования
  - Response lag отслеживается с "первого заигноренного" сообщения и записывает response lag только при ответе менеджера клиенту
  - Поддерживаются уведомления как клиентов которые были зарегестрированы на сайте, так и новых которые связались с магазином через Авито
  - Клиент может открыть несколько разных типов чатов -> нагрузка менеджера мериется количеством клиентов закрепленных за менеджером, а не открых с ним
    чатов
  - Если сообщение уже прочитано менеджером то оно ему не отправляется на почту, а просто обновляет метрики.
Ценность проекту:
  - Минимизация шанса "неувиденных" сообщений менеджером, а также распределение нагрузки между менеджерами

## Features -- опущено

## Архитектура
Все основной функционал находитя в приложении chat, который можно разделить на 3 этапа
• Первичная валидация в контроллере
• Выборка сообщений для отправки, аутентификация-авторизация
• Отправка сообщений на email

Изначально данные приходят в контроллер, после чего происходит первичная валидация сообщения. После чего отправляется в очередь на пожготовку к отправке.
Отправка сообщений происходит пачкой, устанавливаются лимиты отправки(максимальное число отправляемых сообщей из 1 чата)
После авторизации и аутентификации сообщений клиента сообщения обрастают необходимыми данными для преобразования их в email.
Затем происходит отправка уведомлений на email адрес менеджера по SMTP протоколу через Яндекс SMTP сервер.
Определяется успешность-провальность отправки. При неудаче сообщения могут быть отправлены на Retry очередь, если ошибка была из за ошибок SMTP протокола
