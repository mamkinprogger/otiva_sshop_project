# Нагрузочное тестирование модуля Chat  
  
## 1. Цель тестирования  
  
В рамках данного модуля нагрузочного тестирования проверяется отказоустойчивость модуля `chat`.  
Реализован сценарий получения сообщений через `webhook`.  
В ходе тестирования проверяется отказоустойчивость двух основных этапов:  
  
- **Webhook Response (AvitoApi)** — способность webhook-обработчика принимать и обрабатывать входящие запросы под нагрузкой.  
      
- **Notification Send** — способность всей цепочки отправки сообщений обрабатывать нагрузку без накопления критической очереди необработанных сообщений.  

  
## 2. Определённые Baseline  

***Выявленный лимит: (VUs когда начинают появляться первые ошибки)\*0.7***    

|Сценарий|Baseline|  
|---|---|  
|`webhook-resp`|500 VUs|  
|`notif-send`|200 VUs|  
  
  
### 2.1. Webhook Response  
Для сценария `webhook-resp` установлен Baseline — **500 VUs**. -> стабильность обработки входящих webhook-запросов от AvitoApi.  
  
### 2.2. Notification Send  
Для сценария `notif-send` установлен Baseline — **200 VUs**.  
  
Условия тестирования:  
- Количество менеджеров — 8.  
- Количество Celery-воркеров — 8.  
- Один менеджер соответствует одному воркеру.  
  
В качестве наиболее достоверной метрики отказоустойчивости отправки сообщений был взят показатель:  
`avg pending msgs for manager` — среднее количество ожидающих отправки сообщений для одного менеджера.  
  
Для данной метрики установлен Threshold — **15 сообщений**.  
  
Обоснование выбора Threshold:  
Ограничение одного Celery-воркера составляет 15 сообщений за одну операцию получения задач на отправку. Поэтому значение 15 используется как контрольный порог накопления ожидающих сообщений для менеджера.
